# 人物级与任务级预检

## 两层检查的用途

人物级预检回答“这个入口当前能加载什么，能否进入现有动作管线”。任务级预检回答“这个人物在本次动作、服装、机位和背景配置下是否满足生产门槛”。前者通过不能替代后者，也不能证明全部动作和角度都没有穿模。

人物级报告以独立 `subject_id` 为单位。159 是人物入口数量；130 是依赖归档组数量；历史 `supported_v6 / provisional_direct / unsupported` 是旧适配分类，不是这次实测结果。新报告不覆盖历史分类，也不自动启用队列。

## 新环境先检查所有人物

如需重新诊断，先按 FROM_ZERO.md 安装环境、完整解包素材，并配置 `BLENDER_BIN` 和 `VIDEO_ROOT`。从代码仓库运行：

```bash
python scripts/preflight_subjects.py \
  --assets /data/VideoMatting-Assets \
  --video-root "$VIDEO_ROOT" \
  --output /data/audits/subjects-run-001 \
  --workers 4 --threads 4 --timeout 600
```

每次指定新的输出目录；脚本拒绝覆盖旧审计。`--subject-ids ID1 ID2` 可用于修复后的局部复查，不能当作全部 159 人通过。CPU 进程数和每进程线程数可降低；不使用 GPU，不读取或修改生产队列，不保存 Blend 源文件，不产生生产 DONE。

检查包括加载、当前可见服装/头发、活动材质贴图、骨架及当前生成器的 10 个必要控制器、有限且非空的静态包围盒。控制器和活动贴图通过后，再运行随仓库提供的一套 120 帧代表性动作：衣物守卫与四肢变形检查覆盖全部 120 帧，几何运动检查采样 5 帧。三张 CPU 诊断图分别为全身正面、半身 45°、头发正面；320×180、2 samples，独立诊断相机（按世界坐标放置，并未统一所有人物自身朝向），不能用于 2K 发丝质量验收。不能生成动作的人物只出静态图。

| 新状态 | 含义与后续动作 |
|---|---|
| `ready_for_task_preflight` | 本次人物检查无阻断，仍须对每条生产任务预检；不等于生产验收通过 |
| `needs_adapter` | 当前生成器必要控制器缺失，需要原生动作适配；骨骼语义齐全也不能直接放行 |
| `needs_asset_repair` | 当前活动贴图无法解析，修复素材/路径后复查 |
| `needs_quality_review` | 结构能进入管线，但衣物、变形、头发、加载警告或诊断图等仍有问题；查看 blocking_checks |
| `inspection_failed` | 检查进程失败/超时或无法完成；不得当作通过 |

状态有优先级，单人可以有多个问题。检查详细的 `checks`、`blocking_checks`，不要只读取汇总标签。`production_eligible=false` 是刻意保留：人物级审计从不授予生产资格。

输出包含 `progress.json`、`results.jsonl` 和每人物目录中的 `report.json`、三张诊断图、日志。日志可能包含本机路径；对外发布时使用脱敏副本。修复后保留旧报告，使用新目录复检。

## 每次实际执行都强制任务预检

单卡、多卡和每卡多进程使用同一个 worker，因此门槛一致。每条实际任务以及重试都会：

1. 验证人物登记、动作设计与素材路径，并新建工作缓存和本次随机标识。
2. 运行完整低分辨率预检序列，核对帧数量与连续性。禁止 `debug_skip_geometry_qc`，禁止稀疏 `prepass_render_frames`。
3. 核对人物、动作、帧数和本次标识；检查几何运动、全部帧四肢变形、全部帧衣物守卫、碰撞门槛、动作幅度及终段稳定性、头发适配和相关构图检查。密集通用碰撞检测为采样检查，不能称为所有表面所有帧的碰撞证明。
4. 核对输入路径、文件大小、修改时间及任务配置没有改变，再保存 `sample/task_preflight.json`。这是普通文件变更检测，不是整个依赖树的密码学内容校验。
5. 通过后才进入 1920×1080 最终渲染；最终阶段再次执行生成器质量检查，并核对同一次标识、完整帧和输出设置。

`task_preflight.json` 的 `passed` 仅表示预检通过；最终完成仍以完整输出和 DONE 为准。`running` 表示该次预检尚未获得通过证明，也可能已异常退出，结合队列状态与日志判断。再次执行前会把旧预检记录保存至 `sample/preflight_history/`。失败任务继续使用原有暂停/失败机制，不自动降低阈值或绕过守卫。

已有 DONE 的任务会直接跳过，不重新渲染或重新检查；需要改变已完成结果时创建独立版本输出。独立 `run_demo.py` 可只输出一张最终图，但仍运行动作与生成器质量检查；它不是生产 worker 的完整预检证明。

## 已有工作目录续跑与代码更新

`prepare_workspace.py` 只负责新目录，复制当前 tools；不要用它覆盖已有 jobs.sqlite。`render_control.py check/start/run` 和多卡入口拒绝没有任务预检 v1 的旧工作目录。只更新仓库 README 不会自动升级旧工作目录。

在确认工作目录的 supervisor 与 Blender 都停止、队列没有活跃任务后，备份原 tools、SQLite 一致性快照、setting 与日志；保留工作目录特有的 `tools/asset_preflight_classified.tsv`。把本版 tools 更新到该工作目录，恢复其人物登记表，并核对旧队列动作目录和配置兼容性。不要覆盖 jobs.sqlite、素材、配对清单或输出。再执行 `render_control.py check`，先验证一个明确选择的任务，然后才恢复调度。原服务器的生产目录本次未执行此迁移，也未开始全量渲染。

当前衣物守卫对无法识别下装覆盖关系的人物采用 `needs_review`，包括部分穿裤子的人物；这不证明它们已经穿模，也不能直接忽略该状态。适配器或守卫修复需要另行验证。

本次 [159 人实际检查结果](SUBJECT_PREFLIGHT_RESULTS.md)：1 人可进入任务预检、98 人缺少控制器、11 人活动贴图异常、48 人动作/衣物待修复、1 人未找到可见绑定网格。原历史分类不变，未开始全量渲染。
